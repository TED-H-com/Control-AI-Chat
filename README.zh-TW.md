# Control AI Chat

[English](README.md) · [繁體中文](README.zh-TW.md) · [日本語](README.ja.md)

在自己的基礎架構上，使用自己的模型憑證執行的受治理 AI 聊天系統。

員工可在同一個工作空間使用支援的模型目錄。公司可控制各群組能使用哪些已設定模型、
費用多少，以及稽核人員看得到什麼。除了所選功能必須使用的對外連線，應用程式內容都留在您的
基礎架構：已設定模型供應商的 API 要求；透過 SMTP 將設定與重設連結寄到使用者自己的信箱；
管理員要求從網址撰寫助理時，擷取一個公開網頁；標準模式下 Caddy 的 ACME 流量；以及
Tunnel 模式下的 Cloudflare Tunnel 流量。

> **請使用自己的模型供應商憑證。系統會將完整憑證加密儲存在部署的資料庫中，API 絕不會完整回傳。**

## 它做什麼

每個提示詞在送到供應商之前都會受檢查，每個回覆在送到使用者之前也會受檢查。

```
瀏覽器 → 前置閘道 → 預算保留 → 供應商 → 後置閘道 → 使用者
             │            │                   │
             └────────────┴──── 稽核紀錄（雜湊鏈） ┘
```

- **閘道**會偵測電子郵件地址、電話號碼、支付卡號碼與國民身分識別號碼等個人識別資料；API 金鑰與私密金鑰等機密憑證；
  原始碼；`RESTRICTED` 與 `CONFIDENTIAL` 等明確分類標頭；以及提示詞注入。接著套用處置：`允許` → `標記` →
  `遮蔽` → `替換` → `警告` → `阻擋` → `需經核准`。遮蔽是單向處理：保留語境的佔位符會傳給供應商並留在回覆中，不會還原成原文。
- **稽核紀錄**只能附加，且以雜湊鏈串接，因此篡改可被偵測，而不只是被勸阻。工作空間擁有者與法遵審核者
  可匯出 CSV、JSON 或 NDJSON 檔案。系統沒有外部雜湊錨點；如果攻擊者能改寫整個資料庫並重算鏈結，
  就不在這項保證範圍內。
- **預算引擎**在呼叫供應商前保留費用，並在事後結算實際用量，即使使用者在回覆途中關閉分頁也一樣。
  如果結算金額高於保留額，系統會記錄並標示需要對帳，不會隱瞞。
- **存取控制**以群組為單位，同時涵蓋模型與供應商；因此可以讓某個團隊使用 Anthropic 但不能使用
  OpenAI，或只能使用較便宜的模型。
- **模型存取**只使用 API。內建供應商為 OpenAI、Anthropic、Google、xAI、Venice、OpenRouter 與 NVIDIA；
  管理員也可設定通過驗證的公開 HTTPS 基底網址。
- **上傳檔案**可從 PDF、DOCX、XLSX、PPTX、純文字、CSV 與 Markdown 擷取文字。擷取出的文字會先
  通過閘道，才會傳給模型。
- **資料保留**以有上限的每小時批次執行，直到清完各工作空間的積壓。超過工作空間保留期限的對話標題、
  訊息文字與上傳檔案內容會被銷毀，資料列、時間戳與稽核事件則會保留。工作空間擁有者或法遵審核者可在「保留政策」
  畫面建立或解除法律保存，範圍可為整個工作空間、使用者、對話及其附件、專案，或以工作空間時區計算的
  日期範圍。管理員不能建立或解除法律保存。銷毀資料的語句會再次檢查法律保存，因此最後一刻才建立的
  法律保存仍然有效。

## 帳號與存取復原

登入使用本機帳號：密碼、選用的 TOTP 多因素驗證，以及針對重複失敗的帳號鎖定。

- 工作空間擁有者或管理員在「使用者」畫面建立帳號。主控台會顯示一次性設定連結，有效期為 7 天；如已設定
  SMTP，也會以電子郵件寄出。受邀者在 `/setup` 設定密碼後即可登入。
- 工作空間擁有者可為任何其他人建立有效期 24 小時的重設連結；管理員只能為一般成員建立。沒有人可以為自己建立連結。
- 設定 SMTP 後，登入畫面會顯示「忘記密碼？」。無論信箱是否存在，回應都相同；系統會寄給使用中的帳號一個
  有效期 1 小時的重設連結，每位使用者最快每 5 分鐘一次。
- 每個設定或重設連結都只能使用一次。新連結會取代該使用者同類型中尚未使用的連結，伺服器只儲存權杖的
  SHA-256 雜湊。透過重設連結設定密碼會結束該使用者的所有工作階段；在已登入狀態變更密碼，則會結束其他工作階段。
- 只有工作空間擁有者可以指派法遵審核者角色。工作空間擁有者可管理所有其他帳號；管理員可管理一般成員與其他管理員。只有工作空間擁有者可以
  將法遵審核者停權、移除、強制登出、變更角色或傳送連結。沒有人可以將工作空間擁有者停權、移除、變更角色或傳送連結。每位使用者，
  包括工作空間擁有者，都可以登出自己的工作階段；沒有其他人可以強制登出工作空間擁有者。

## 您需要準備什麼

- 一台您可控制的 Linux `amd64` 或 `arm64` 主機。Ubuntu Server 24.04 LTS 是參考作業系統。2 vCPU 與
  4 GB 記憶體是支援的起始規格，並非通用容量保證；請依實際並行量與上傳／擷取量調整並進行負載測試。
- 程式碼簽出目錄與 Docker root 所在檔案系統都至少保留 10 GiB，這只是安裝下限；正式上線前仍須針對
  資料庫／WAL、上傳檔案、映像、暫存作業與異地備份完成容量規劃。SQLite 與 WAL 必須放在真正的本機檔案系統。
- 一個指向該主機的網域名稱。**HTTPS 是必要條件**，不是建議：工作階段 Cookie 帶有 `Secure` 屬性與
  `__Host-` 前綴，因此無法透過純 HTTP 登入。標準 Caddy 會自動取得憑證；專用 Cloudflare Tunnel 模式使用
  Cloudflare 邊緣 TLS，並只在主機 loopback 上提供 Caddy。
- 主機時間已同步，且使用完全乾淨的正式版本簽出，或不含 Git 歷史的原始碼封存檔。
- Docker 與 Compose 外掛程式。Direct Caddy 模式要求主機 TCP 80/443 與 UDP 443 可用；專用 Tunnel 模式要求
  Engine 28.0.0+、Compose 2.24.4+、Python 3，以及可用的 loopback TCP 18080。
- 至少一組您自己的 API 供應商憑證。
- [支援部署標準](docs/SUPPORTED-DEPLOYMENT.md)：v0.1.x 的正式基準，以及客戶／導入夥伴的驗收清單。
- [部署指南](docs/DEPLOY.md)：安裝、升級、備份與維運。
- [Azure](docs/cloud/azure.md)、[AWS](docs/cloud/aws.md)、[Google Cloud](docs/cloud/gcp.md)、
  [Oracle Cloud](docs/cloud/oracle.md) 與[前端代理](docs/cloud/front-door.md)的雲端部署範例。

Cloudflare 與 Vercel 可放在應用程式前方提供 DNS、CDN 或 TLS。共用 VM 若適合使用專用、本機管理的
Tunnel，可選擇受版本控制的 `install.sh --cloudflare-tunnel` 模式。安裝器只會準備 loopback 上的應用程式
origin；客戶核准的 Cloudflare 帳號、Tunnel 憑證、服務與 DNS 仍須人工處理。Cloudflare 與 Vercel 無法**承載**
應用程式本身：應用程式使用檔案型資料庫、在長時間執行的行程中以計時器執行背景工作，並在記憶體中保留已解密的
政策狀態；這些條件在邊緣或無伺服器執行環境中都不存在。

## 安全性立場

- 供應商憑證以 AES-256-GCM 封存，並同時繫結至工作空間與供應商，因此被竊取的密文無法在其他欄位重播。
  完整憑證永遠不會經由 HTTP 回傳；主控台只顯示最後四個字元。
- 保護供應商憑證的金鑰，刻意與作為稽核鏈根的金鑰分開，因此可以在不破壞稽核歷史的情況下輪替外洩的供應商憑證金鑰。
- 已儲存的供應商憑證以具版本的金鑰封存。如果啟用中的憑證使用設定環境不持有的金鑰版本，應用程式會拒絕啟動；
  因此誤刪金鑰會在啟動時安全失敗，而不是在未察覺的情況下讓已儲存的憑證無法讀取。
- 移除舊金鑰前，維運人員可執行 `scripts/compose.sh exec -T app npm run check-key-coverage`。
  此命令只讀取資料庫，並列出儲存的供應商金鑰版本：結束碼 0 表示目前持有所有列出的版本，1 表示設定的金鑰缺少某個
  已儲存版本，2 表示無法檢查資料庫或設定。
- [部署指南](docs/DEPLOY.md)中的 `PROVIDER_CREDENTIAL_KEY` 輪替，可以用
  `scripts/rotation-rehearsal.sh` 在已提交 `HEAD` 的可拋棄式安裝上進行端到端演練，包括過早移除金鑰時拒絕啟動，
  以及其後的復原。
- 系統不會執行使用者或模型產生的程式碼；程式碼區塊只會以程式碼格式顯示。附件只會以通過閘道檢查的擷取文字傳給模型。
- **我們沒有任何認證。** 本軟體實作的控制措施可以支援您的合規計畫，但它不會讓您取得 SOC 2、HIPAA 或 ISO 認證，
  我們也永遠不會這樣宣稱。
