# Control AI Chat

[English](README.md) · [繁體中文](README.zh-TW.md) · [日本語](README.ja.md)

自社のインフラ上で、自社のモデル認証情報を使って動作する、ガバナンス付き AI チャットです。

従業員は、対応モデルカタログを一つのワークスペースから利用できます。会社は、各グループが利用できる設定済みモデル、
費用、および監査担当者に表示する情報を管理します。アプリケーションのデータは、選択した機能に必要な次の外部接続を除き、
自社インフラ上に残ります。設定済みモデルプロバイダーへの API リクエスト、SMTP によるセットアップリンクとリセットリンクの
本人アドレスへの送信、管理者が公開 Web ページからアシスタントの下書きを作成するよう指示したときのページ取得、標準モードの Caddy による
ACME 通信、および Tunnel モードの Cloudflare Tunnel 通信です。

> **モデルプロバイダーの認証情報は自社で用意します。完全な認証情報はデプロイ先のデータベースに暗号化して保存され、
> API から完全な形で返されることはありません。**

## 主な機能

すべてのプロンプトはプロバイダーへ送られる前に検査され、すべての応答はユーザーに届く前に検査されます。

```
ブラウザ → 事前ゲート → 予算引当 → プロバイダー → 事後ゲート → ユーザー
              │             │                        │
              └─────────────┴──── 監査ログ（ハッシュチェーン） ┘
```

- **ゲート**は、メールアドレス、電話番号、決済カード番号、国民識別番号などの個人識別子、API キーや秘密鍵などのシークレット、
  ソースコード、`RESTRICTED` や `CONFIDENTIAL` などの明示的な分類ヘッダー、およびプロンプトインジェクションを検出します。
  次の処理を適用します。`許可` → `フラグ` → `マスキング` → `置換` → `警告` → `ブロック` → `承認が必要`。マスキングは一方向です。
  文脈を保つプレースホルダーがプロバイダーへ送られ、応答にも残り、元の値は復元されません。
- **監査ログ**は追記専用で、ハッシュチェーンで連結されるため、改ざんを検出できます。ワークスペース所有者とコンプライアンス審査担当は、
  CSV、JSON、または NDJSON ファイルとしてエクスポートできます。外部ハッシュアンカーはないため、データベース全体を書き換えてチェーンを
  再計算できる攻撃者は、この保証の対象外です。
- **予算エンジン**は、プロバイダー呼び出しの前に費用を引き当て、実績を呼び出し後に精算します。ユーザーが応答の途中でタブを閉じた場合も
  同様です。精算額が引当額を超えた場合は、隠さずに記録し、要照合として扱います。
- **アクセス制御**はグループ単位で、モデルとプロバイダーの両方に適用されます。たとえば、特定のチームに Anthropic だけを許可して
  OpenAI は許可しない、または低価格のモデルだけを許可する、といった運用ができます。
- **モデルアクセス**は API のみを使います。組み込みプロバイダーは OpenAI、Anthropic、Google、xAI、Venice、OpenRouter、
  NVIDIA です。管理者は、検証済みの公開 HTTPS ベース URL も設定できます。
- **アップロード**された PDF、DOCX、XLSX、PPTX、プレーンテキスト、CSV、Markdown からテキストを抽出します。
  抽出したテキストは、モデルへ送る前にゲートを通過します。
- **データ保持**は、各ワークスペースの滞留分がなくなるまで、上限付きのバッチで 1 時間ごとに実行されます。保持期間を過ぎた会話タイトル、
  メッセージ本文、およびアップロードファイルの内容は破棄されますが、各行、タイムスタンプ、監査イベントは残ります。ワークスペース所有者または
  コンプライアンス審査担当は、「保持ポリシー」画面でリーガルホールドを設定または解除できます。対象は、ワークスペース全体、ユーザー、
  会話とその添付ファイル、プロジェクト、またはワークスペースのタイムゾーンに基づく日付範囲です。管理者はリーガルホールドを設定または解除できません。
  データを破棄する SQL 文内でホールドを再確認するため、直前に設定したホールドも有効です。

## アカウントとアクセス復旧

サインインにはローカルアカウントを使います。パスワード、任意の TOTP 多要素認証、および失敗が繰り返されたときのロックアウトに対応しています。

- ワークスペース所有者または管理者が「ユーザー」画面でユーザーを作成します。コンソールには有効期間 7 日の 1 回限りのセットアップリンクが表示され、
  SMTP 設定時はメールでも送信されます。招待されたユーザーは `/setup` でパスワードを設定し、その後サインインします。
- ワークスペース所有者は、自分以外のすべてのユーザーに有効期間 24 時間のリセットリンクを作成できます。管理者が作成できるのはメンバー用のみです。
  自分自身のリンクは誰も作成できません。
- SMTP 設定時は、サインイン画面に「パスワードを忘れた場合」が表示されます。アドレスが存在するかどうかにかかわらず同じ応答を返し、有効な
  ユーザーには有効期間 1 時間のリセットリンクをメールで送信します。送信頻度はユーザーごとに 5 分に 1 回までです。
- セットアップリンクとリセットリンクはすべて 1 回限りです。新しいリンクを発行すると、そのユーザーの同種の未使用リンクは置き換えられます。
  サーバーに保存されるのはトークンの SHA-256 ハッシュのみです。リセットリンクでパスワードを設定するとそのユーザーの全セッションが終了し、
  サインイン中のパスワード変更では他のセッションが終了します。
- コンプライアンス審査担当ロールを割り当てられるのはワークスペース所有者だけです。ワークスペース所有者はその他のすべてのアカウントを管理でき、管理者はメンバーと
  他の管理者を管理できます。コンプライアンス審査担当の停止、削除、強制サインアウト、ロール変更、リンク送信ができるのはワークスペース所有者だけです。
  ワークスペース所有者を停止、削除、ロール変更したり、ワークスペース所有者へリンクを送信したりすることは誰にもできません。ワークスペース所有者を含むすべてのユーザーは自分のセッションをサインアウトできますが、
  ワークスペース所有者を他のユーザーが強制サインアウトさせることはできません。

## 必要なもの

- 自社が管理する Linux `amd64` または `arm64` ホスト 1 台。参照 OS は Ubuntu Server 24.04 LTS です。2 vCPU / 4 GB メモリは
  サポートされる開始構成であり、一律の容量保証ではありません。実際の同時実行数とアップロード／抽出量に合わせてサイジングし、負荷試験を行ってください。
- チェックアウトと Docker root の各ファイルシステムに、インストール時の最低条件として 10 GiB 以上の空き容量が必要です。本番稼働前に、
  DB／WAL の増加、アップロード、イメージ、一時作業、オフホストバックアップを含む容量計画も必要です。SQLite と WAL は実ローカルファイルシステム上に置いてください。
- そのホストを指すドメイン名。**HTTPS は必須**であり、推奨ではありません。セッション Cookie には `Secure` 属性と `__Host-` プレフィックスが付くため、
  平文 HTTP ではサインインできません。標準 Caddy は証明書を自動取得します。専用 Cloudflare Tunnel モードでは Cloudflare エッジ TLS を使用し、
  Caddy はホストの loopback のみに公開します。
- ホスト時刻が同期済みで、正式リリースのチェックアウトが完全に clean であること、または Git 履歴を含まないソースアーカイブ。
- Docker と Compose プラグイン。Direct Caddy ではホストの TCP 80/443 と UDP 443 が空いている必要があります。専用 Tunnel モードでは
  Engine 28.0.0+、Compose 2.24.4+、Python 3、および空いている loopback TCP 18080 が必要です。
- 自社の API プロバイダー認証情報が 1 つ以上。
- [サポート対象デプロイ標準](docs/SUPPORTED-DEPLOYMENT.md)：v0.1.x の正式ベースラインと、顧客／導入パートナー向け受入チェックリスト。
- [デプロイガイド](docs/DEPLOY.md)：インストール、アップグレード、バックアップ、運用。
- [Azure](docs/cloud/azure.md)、[AWS](docs/cloud/aws.md)、[Google Cloud](docs/cloud/gcp.md)、
  [Oracle Cloud](docs/cloud/oracle.md)、[フロントドアプロキシ](docs/cloud/front-door.md)向けのクラウド別手順。

Cloudflare や Vercel は、DNS、CDN、TLS を提供するフロントドアとして前段に置けます。共有 VM で専用のローカル管理 Tunnel がより安全な場合は、
追跡対象の `install.sh --cloudflare-tunnel` モードを利用できます。インストーラーが準備するのは loopback 上のアプリケーション origin のみです。
顧客承認済みの Cloudflare アカウント、Tunnel 認証情報、サービス、DNS は手動で用意します。Cloudflare や Vercel でアプリ自体を**ホスト**することはできません。
アプリケーションはファイルベースのデータベースを持ち、長時間稼働するプロセス内でタイマーによるバックグラウンドワーカーを動かし、復号済みのポリシー状態をメモリに
保持します。これらはエッジやサーバーレスのランタイムには存在しません。

## セキュリティについて

- プロバイダー認証情報は AES-256-GCM で封印し、ワークスペースとプロバイダーの両方に紐付けます。そのため、盗まれた暗号文を別の枠で再利用することは
  できません。完全な認証情報が HTTP 経由で返されることはなく、コンソールに表示されるのは末尾 4 文字だけです。
- プロバイダー認証情報を保護する鍵は、監査チェーンのルート鍵と意図的に分離されています。監査履歴を壊さずに、漏えいしたプロバイダー認証情報の鍵をローテーションできます。
- 保存済みのプロバイダー認証情報は、バージョン付きの鍵で封印されます。有効な認証情報が、設定環境にない鍵バージョンを使っている場合、アプリケーションは起動を
  拒否します。これにより、鍵を誤って削除した場合は、保存済み認証情報が気づかないうちに読み取れなくなるのではなく、起動時にフェイルクローズします。
- 古い鍵を削除する前に、運用担当者は `scripts/compose.sh exec -T app npm run check-key-coverage` を実行できます。
  このコマンドはデータベースを書き換えずに読み取り、保存済みのプロバイダー鍵バージョンを一覧表示します。終了コード 0 は表示されたすべてのバージョンを保持していること、
  1 は設定済みの鍵に保存済みバージョンが不足していること、2 はデータベースまたは設定を検査できなかったことを示します。
- [デプロイガイド](docs/DEPLOY.md)に記載した `PROVIDER_CREDENTIAL_KEY` のローテーションは、
  `scripts/rotation-rehearsal.sh` を使い、コミット済み `HEAD` の使い捨てインストールでエンドツーエンドのリハーサルを実施できます。鍵を早く削除しすぎた場合の起動拒否と、
  そこからの復旧も含みます。
- ユーザーまたはモデルが生成したコードは実行されず、コードブロックとして表示されるだけです。添付ファイルは、ゲート検査済みの抽出テキストとしてのみモデルへ送られます。
- **当社は認証を一切保有していません。** 本ソフトウェアは御社のコンプライアンス活動を支える統制を実装しますが、御社が SOC 2、HIPAA、ISO の認証を取得したことにはならず、
  当社がそのように主張することもありません。
